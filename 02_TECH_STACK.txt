KUBERNETES

- Kubernetes
- kubectl
- Helm

Deployment approach for Stage 3:
1. Raw Kubernetes YAML first (Deployments, Services, ConfigMaps/Secrets as needed)
2. Then package the working manifests into a Helm chart under helm/nexops

Helm is used to manage configurable values such as:
- image repository / tag
- replica count
- service ports
- resource requests / limits

Local development:
- existing local/POC Kubernetes environment

Final deployment:
- AWS EKS

AI

Use an LLM API.

The exact provider/model can be selected during implementation.

AI is responsible for:
- incident analysis
- root cause explanation
- evidence interpretation
- fix recommendation

AI must return structured output.

AI must NOT receive unrestricted shell access.

AI must NOT directly execute arbitrary kubectl commands.


DATA

Avoid a database initially.

Add PostgreSQL or another database only when the project actually needs persistent application/platform data.

Do not introduce Redis/Kafka/etc. without a clear reason.


IMPORTANT

Do not add technologies just to make the technology list larger.

Prefer:
simple
reliable
understandable
production-style
